# 评审与验收指南

## 范围与角色

评审对象是 CURRENT_BASELINE.md 中已有编号的问题，不是对整个项目重新审计。每个编号应包含原始文档及段落、原始断言、待核实证据和边界。复杂断言可以拆成同一编号的子项，但不能借此增加新主题。

Claude Code 鉴定问题并复核修复；Codex 独立核实后实施当轮已授权范围内的最小修复并执行贡献门禁；人工决定需求变化、产品边界、预算和无法确认的设计取舍。工具名称与模型名称分别记录；使用 DeepSeek 时注明实际模型。不得声称模型结论已获得人工确认。

只处理文档已有问题。新建议在对话中单独列为“待人工判断”，不得写入问题清单或任何报告，包括非阻塞观察、表格、结论和下一步；也不得加入修复或验收范围。

## 固定基线与交接

每轮记录仓库相对路径、完整基线提交 SHA、分支、工作区状态和问题来源版本。只写 HEAD 不足以描述脏工作区；存在待评审改动时同时记录差异摘要、文件状态及补丁或文件内容哈希。忽略文件也须单独登记，Git diff 不会覆盖它们。

先核对当前版本与原报告版本。公开文档或工具配置变更可以单独说明；不能把另一提交的结论直接套用到当前源码。未读取的资料、未执行的命令、历史测试结果须明确标记，不补写为本轮证据。

默认材料目录为 `.private/review/current/`。其他轮次通过命令参数指定仓库相对目录。CURRENT_BASELINE.md 是问题范围契约，REVIEW.md 是鉴定，FIX_REPORT.md 是修复交接，VERIFICATION.md 是复核。各角色不覆盖对方报告；历史原始报告保持原样。

## 问题鉴定

逐项使用“成立、部分成立、不成立、证据不足”。依据包括源码位置、调用路径、契约或可复现验证。原报告的严重性与新鉴定分别记录；文档过期、实现缺陷、范围外预期不能混为一谈。

部分成立的问题分别写明成立与不成立部分。仅“成立”和“部分成立”中明确成立、可安全处理且在当轮任务授权范围内的部分进入修复；审计元数据模式不另设逐条 finding 人工批准节点。证据不足应补证或延期，不允许猜测修复。需求取舍不因报告评级而自动授权。

不得读取 `.env`、本地认证配置或私有凭据。验证用脱敏材料或确定性夹具。公网 API、模型计费测试、安装依赖和远程操作须符合当前用户授权；不要由评审命令默认执行。

Claude Code 自身的鉴定与复核会调用已配置的模型 API。报告中的“未执行公网模型评测”只描述应用验证，不能写成“没有模型 API 请求”。CLI 对第三方模型的成本估算不等于供应商实际账单。

只读 Git 命令在仓库根目录执行，可使用共享配置允许的 `git rev-parse HEAD`、`git status --short`、`git diff --name-only` 和 `git diff --stat`。命令被拒绝后停止该验证，记录“无法验证”及需要的权限；不得改换脚本或反复尝试绕过拒绝。未获权限的补充证据不能偷偷增加为原问题的验收条件。

## 修复与复核

Codex 的 FIX_REPORT.md 记录问题编号、最小改动、完整修复提交或差异标识、命令结果和残留限制。没有修改的问题注明原因，不以“所有检查通过”替代逐项证据。

Claude Code 对照原始断言、REVIEW.md 的成立部分与实际差异逐项复核，使用“通过、未通过、无法验证”。只针对该问题检查修复效果及直接回归；不引入其他优化。文档性修复可通过内容核对完成，不需要编写镜像测试。

脏工作区修复的测试应在记录的差异上执行；`git diff --exit-code` 在提交修复前不能作为要求工作区为空的通用门禁。忽略的演练文件采用内容哈希，不虚构 Git 提交。

## 贡献门禁

Issue #80 的本地审计元数据模式只推进四报告与状态，不执行产品修复或远端交付；其 `completed` 仅表示本轮审计结论完整，不是 CI 或发布门禁。明确可安全处理的缺陷可按当轮用户授权实施；需求扩展、设计取舍和不安全处置须 `DEFERRED`，不因省略 finding 人工批准节点而越权。机器字段、两轮预算、历史隔离与最小摘要见[需求文档](audit-metadata-requirements.md)及[评估说明](audit-metadata-assessment.md)。

公开变更遵循 CONTRIBUTING.md；本地私有报告无需为每次写入创建 PR。是否运行完整门禁按贡献规则与影响判断；PR 最终仍需现有 required CI，文档变更不跳过保护规则。

当前 CI 使用 Node.js 22，执行依赖安装、生产依赖安全审计、构建、Tier A、repository、contract、collaboration、harness、agentic、reliability、performance 评测以及已跟踪文件生成差异检查。准确命令以 `.github/workflows/ci.yml` 为准；联网安全审计不是离线测试，公网模型评测不属于 required CI。

验证报告区分问题专项验证、本地贡献检查和远程 CI。未执行的检查写“未执行”及原因。通过 CI 不能证明业务生产可用、SLO 达标或原报告所有问题已修复。

## 隐私与操作限制

只提交公共规则、模板和不含认证信息的共享配置。提交前核对 Git 暂存内容，排除密钥、本机绝对路径、私人对话、实际评审报告和演练材料。不要为了共享工作流读取其他项目的聊天。

Claude Code 的文件权限用于约束工具操作，不是操作系统级隔离。评审不提交、推送、合并或修改产品文件；额外命令的权限提示按实际需要由人工判断。GitHub 发布规则与模型服务传输边界不同：未上传 GitHub 的上下文仍可能发送至所配置的模型 API。

权限路径和工具边界参阅 [Claude Code 官方权限说明](https://code.claude.com/docs/en/permissions)，命令文件机制参阅 [Claude Code 官方命令与技能说明](https://code.claude.com/docs/en/slash-commands)。实际行为仍须用当前已安装版本验证。
