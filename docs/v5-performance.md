# V5 秋招性能补充

> 最新正式版本：v0.18.0@a0a7d670dec014235fc2c62e43f797ac6e105220，完整秋招V5的功能/性能/证据与发版核对见 [发布审计](v5-performance-release-audit.md)。v0.17.0记录为基础版本历史。

## 改了什么

在完整V5 v0.17.0基础上加入独立探针有界并发及可复跑的配对评测。长期SLO与生产级部署不属于本轮秋招验收范围；完整发布事实已在发布审计核对。

ProbeScheduler默认1，CLI显式 `--probe-concurrency 4` 可选1～4。只有可信注册计划显式 `parallelSafe: true`、`sideEffectFree: true`、`snapshotConsistent: true` 才参与并行；这些是宿主声明，运行时不会凭空证明外部API只读或跨源一致性。未声明计划是独占屏障；相同origin（包括不同租户/路径）始终串行。默认1保持原注册/variant真实I/O顺序。返回按注册顺序，持久证据按实际完成顺序。

同Scheduler多次tick排队；上限是每实例、每进程的探针池，不宣称跨进程探针互斥。slot仍先落盘，禁用/版本变化与取消停止后续请求，存储失败取消并排空已启动任务才返回。原Worker资源锁、审批、模型工具与Reviewer治理保持原链路。

## 为什么

独立HTTP等待可重叠，串行持久化仍限制收益；不是让模型同时执行写工具。只改变并发这个变量，可直接回答优化前后快多少、有没有丢失证据。

## 怎么证明

运行 `npm run eval:performance`；保留原报告可用 `node scripts/performance-eval.mjs .private/performance-v5/自定义新目录`（先build，每次新目录）。两种负载各8个自有loopback验证服务、每计划合法200与缺amount预期400各一次，不创建订单、不调模型；每种模式预热一次不计入，6组AB/BA交替，共每模式96次实际HTTP。计时包含HTTP、JSON持久化、逐条路由和空Worker，排除服务启动/计划注册；两个模式逐例结果摘要一致，所有origin内并发不超过1。

注入40ms负载批次中位时延下降 **70.81%**，配对加速中位数 **3.43倍**，中位吞吐提升 **241.19%**；零注入延迟对照下降 **43.67%**。单请求分位数与批次指标分别统计，不能把批次收益解释为服务端单请求优化。

环境：v24.18.0 / win32 10.0.26200 / AMD Ryzen 5 9600X 6-Core Processor              / 12逻辑CPU。[完整逐对样本与源码摘要](evidence/v5-performance.json)保留两个负载、环境、原报告SHA256；探索候选与失败编译日志私有保留，未替代最终证据。八项新增合同覆盖并发上限/同origin/屏障/默认顺序/tick重入/slot不重放/禁用/取消/失败排空，完整单测173项。CI只要求语义一致、容量和安全合同通过，报告实际收益，不设跨机器速度提升阈值。

发布前[真实模型验收](evidence/v5-performance-live.json)另行证明现有Harness仍运行：健康零模型、临时故障完成、Schema持续异常调查后接管；该单次验收不是模型性能对照。旧v0.17.0与v0.16.0证据原文件不变，分别对应历史tag，不要求旧摘要匹配新代码。

## 尚未解决

六个批次的P95仅为描述性近邻秩分位数，不能证明长期尾时延、统计显著性或生产负载收益。零注入延迟意为responseDelayMs参数为0，仍沿用setTimeout(0)的异步调度并计入测量，包含真实网络/磁盘等待；它不是同步立即响应的纯网络/磁盘基线。本报告是同一代码并发参数1与4的受控对照，不是两个正式版本全产品性能对比；没有付费模型基线，不宣称Token/费用降低。

后续可单独评测健康路由无变更写入消除、批量持久化、增量日志与背压；这些会影响失败恢复和证据落盘，需保留slot先保存、审批账本、原合同复查，再逐项对照。当前本地JSON/有限Schema/注册后端范围不扩展为生产Exactly-once。

### 模型复验的实际边界

live01～03在原任务说明下未收敛，04只澄清UNKNOWN根因的允许边界后仍未收敛；四次均NO_PROGRESS_LIMIT阻断，原失败和摘要完整保留。随后看板加入持久化完整读取状态与既有完成合同，压缩后仍保留任务目标/预算，新增一项跨压缩合同（总173项）。最终live单次通过不等于四次失败不存在，也不证明已唯一定位根因或提升模型成功率；这些是独立收敛治理补充，未用于探针吞吐收益计算。
