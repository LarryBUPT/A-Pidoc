# JD 适配级产品迭代路线

## 迭代原则

每个版本都必须新增一种真实用户价值、一项可验证工程能力和一组评测数据。不能只增加 Agent 数量或更换模型。

## V0：确定性单请求诊断器（当前）

### 用户价值

在固定测试环境中完成一次“失败—定位—修正—复测—报告”。

### JD 适配

- TypeScript、HTTP、JSON、接口设计和自动测试。
- Agent loop、工具调用、状态记忆、权限、重试、Reviewer、Trace。
- 把模糊的“接口报错”拆成可执行步骤。

### 完成门槛

- 6 个固定 Case 和 1 个越权 Case 全部通过。
- CLI 与 HTTP API 都可运行。
- 报告包含 attempts、evaluation 和 trace。

## V1：真实输入与 Pi Reasoner

### 用户价值

用户粘贴 curl/OpenAPI，Agent 可以理解规范并诊断测试环境接口。

### 新增能力

- curl parser、OpenAPI operation parser、JSON Schema 校验。
- `RealHttpTool`：超时、AbortSignal、脱敏、响应大小限制。
- `PiReasoner`：结构化输出、Prompt 版本、模型错误降级。
- 文档分块、混合检索和 rerank；建立 Recall@K 数据集。
- Trace 增加 token、模型、Prompt 版本和工具耗时。

### JD 适配

- 腾讯/美团：模型 API、RAG、后端集成和用户体验。
- 阿里：Context Engineering、召回质量、标准化 SDK/API。
- 抖音：真实工具、结果验证、执行观测和异常恢复。

### 评测

- 至少 30 个冻结 Case，包含可解决、不可解决和恶意输入。
- 与“原始 Pi + 通用 Prompt”比较根因准确率、成功率、平均尝试数和成本。

## V2：项目级 API 联调助手

### 用户价值

从代码仓库自动找到 Axios/fetch/requests 调用，定位配置或实现与规范的差异。

### 新增能力

- Repo Scanner、环境变量引用追踪、调用点定位。
- 生成契约测试；修改代码前后运行测试。
- Worker 进程、任务状态持久化、超时取消和崩溃恢复。
- Debug Agent + Evidence Reviewer；只在复杂任务启用双 Agent。

### JD 适配

- 抖音：代码理解、修改、构建、Verify 和 Harness 状态控制。
- 阿里：任务拆解、反思纠错、多 Agent 取舍。
- 四家共同：完整项目交付与问题排查。

### 评测

- 在 3 个示例仓库中预埋 20 个 API 集成 Bug。
- 测调用点召回率、补丁正确率、测试通过率、平均修复时长。

## V3：契约变更与历史回放

### 用户价值

API/SDK 升级前自动判断哪些调用会坏，并生成迁移测试和风险报告。

### 新增能力

- OpenAPI semantic diff、影响分析、历史任务回放。
- Postgres 保存任务和 Trace；对象存储保存脱敏 Artifact。
- 离线回测、版本对比、错误聚类和归因面板。
- CI 集成，在 PR 中输出契约风险。

### JD 适配

- 阿里/抖音：自动化评测、历史回放、回归验证和归因。
- 腾讯：持续反馈优化。
- 美团：数据处理、监控和稳定迭代。

## V4：团队协作与可运营服务

### 用户价值

研发、测试和技术支持可从 GitHub/Jira/飞书共同发起、跟踪和复用诊断。

### 新增能力

- MCP/Connector 接入工单、代码托管、日志和知识库。
- RBAC、租户隔离、审批、审计、秘密管理。
- 异步任务队列、幂等键、指数退避、熔断和降级。
- 可视化 UI 展示证据、变更和反馈入口。

### JD 适配

- 腾讯：产品体验和作品上线。
- 美团：内部 AI 工具和跨团队交付。
- 阿里：可复用组件与规模化落地。
- 抖音：MCP/API/CLI 原子能力和权限边界。

## V5：持续 API 可靠性 Agent

### 用户价值

从故障后诊断升级为定时探测、异常聚类和主动告警。

### 新增能力

- Scheduler + Queue + Worker，多任务并发和 backpressure。
- OpenTelemetry、SLO、成本预算、缓存与分级模型路由。
- 沙箱/隔离执行、跨环境策略和人工接管。
- 小模型做分类与检索，大模型处理复杂归因。

### JD 适配

- 阿里：高并发、异步、降级和低侵入观测。
- 抖音：稳定性、时延、成本、安全和端边云模型路由。

## 最现实的求职交付计划

| 周期 | 目标 | 对外可展示物 |
| --- | --- | --- |
| 第 1 周 | 完成 V0 并补齐文档 | GitHub 仓库、测试截图、3 分钟 Demo |
| 第 2 周 | curl/OpenAPI 输入 + RealHttpTool | 一条真实沙箱 API 诊断录像 |
| 第 3 周 | PiReasoner + 30 Case 对比评测 | 基线/改造后实验报告 |
| 第 4 周 | 示例仓库扫描和契约测试 | 端到端修 Bug Demo、技术博客 |

V0 已经是可以运行的工程骨架，但真正投递前建议至少完成 V1。V2 做出一个窄而完整的 Repo Case，就足以支撑大量工程追问；V3-V5 保留为架构和产品演进回答，不必在实习投递前全部实现。
